# Debug Notes 4: Two distinct issues

## Issue 1: TypeError at (index):282 — `app.ports.listFiles` is undefined

The outgoing command port `Ports.listFiles` is declared in Ports.elm but NEVER
called anywhere in Main.elm. Elm's `--optimize` flag performs dead-code elimination
and removes unused command ports from the compiled JS. This makes
`app.ports.listFiles` undefined at runtime.

When the JS bridge tries `app.ports.listFiles.subscribe(...)`, it throws:
  TypeError: Cannot read properties of undefined (reading 'subscribe')

This crashes the entire `<script type="module">` block, preventing ALL subsequent
port subscriptions from being registered (listSnapshots, connectNotifications,
disconnectNotifications).

Similarly, `Ports.disconnectNotifications` is declared but never called.

### Fix for Issue 1:
Two approaches:
A) Add `Ports.listFiles ()` calls in Main.elm where resources should be loaded
B) Guard all port subscriptions in index.html with optional chaining

Best approach: BOTH. Add the missing Ports.listFiles calls AND guard subscriptions.

## Issue 2: WASM "unreachable" trap

The browser console shows: `[dyna] WASM module not available: unreachable`

This happens during `loadWasm()` — either during `await init()` or `new DynaClient()`.

The "unreachable" instruction in WASM is generated by:
1. `panic!()` / `unwrap()` on None/Err — compiled to `unreachable` in release mode
2. wasm-bindgen version mismatch between CLI tool and library

Cargo.lock pins wasm-bindgen 0.2.111.
Nixpkgs unstable currently has wasm-bindgen-cli 0.2.105 or 0.2.106.

This is a CRITICAL version mismatch. The Nix-built WASM artifacts were produced
using `pkgs.wasm-bindgen-cli` (0.2.105/106) to process a binary compiled against
wasm-bindgen 0.2.111. The schema format changed between these versions, causing
the "unreachable" trap at runtime.

### Fix for Issue 2:
Pin wasm-bindgen-cli to match the Cargo.lock version (0.2.111).
Use `pkgs.wasm-bindgen-cli.override` or build from source with the correct version.
