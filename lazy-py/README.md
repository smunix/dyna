# lazy-py: Lazy, On-Demand Resource Loader for Dyna

A Pythonic, asynchronous, lazy resource loader for the Dyna distributed CRUD system, with real-time updates via WebSockets.

## 1. Problem Statement

In modern applications, especially those with rich, interactive user interfaces, efficiently managing and synchronizing data between the client and server is a significant challenge. Frontend applications often need to display numerous data resources, but fetching all of them upfront can be slow and wasteful, leading to poor user experience and unnecessary network traffic. Furthermore, once the data is loaded, it can become stale, requiring a mechanism to receive and reflect updates from the server in real-time.

`lazy-py` addresses this by providing a lazy-loading mechanism for resources from a Dyna server. Instead of pre-fetching all possible data, it allows applications to fetch only the resources they need, when they need them. It also establishes a WebSocket connection to the Dyna server to receive live updates, ensuring that the application's state remains synchronized with the server without resorting to inefficient polling.

## 2. Intent and Goals

The primary goal of `lazy-py` is to offer a simple, efficient, and Pythonic way to interact with a Dyna server for applications that require on-demand data loading and real-time updates. Its design philosophy is centered around minimalism and ease of use.

Key goals include:

*   **Lazy Loading**: Minimize initial load times and network usage by fetching resources only when requested.
*   **Real-Time Updates**: Provide a seamless, real-time view of data by leveraging WebSockets for live updates.
*   **Asynchronous API**: Offer a fully `async` API that integrates smoothly with modern Python applications using `asyncio`.
*   **Developer Experience**: Provide a clean, intuitive, and well-documented API that is easy to learn and use.
*   **Robustness**: Ensure reliable connections and graceful error handling.

## 3. Architecture

`lazy-py` acts as a client-side library that communicates with a `dyna-server` instance. It uses HTTP for initial resource fetching and a persistent WebSocket connection for receiving real-time updates.

### Component Diagram

```ascii
+---------------------------+
|   Python Application      |
| (e.g., Web App, Script)   |
+-------------+-------------+
              |
              | (1) Initial Fetch (HTTP GET)
              v
+-------------+-------------+
|        lazy-py            |
|      (LazyClient)         |
+-------------+-------------+
              |\_ (2) WebSocket Connection
              |  (Persistent)
              v
+-------------+-------------+
|        dyna-server        |
+---------------------------+
|      (WebSocket API)      |
+-------------+-------------+
              |
              v
+-------------+-------------+
|      Storage Backend      |
|       (e.g., S3)          |
+---------------------------+
```

### Data Flow

1.  **Initial Fetch**: When the application requests a resource for the first time using `LazyClient.get()`, `lazy-py` sends an HTTP GET request to the `dyna-server` to retrieve the resource. The server fetches the resource from the storage backend, and returns it.
2.  **WebSocket Connection**: The `LazyClient` establishes a persistent WebSocket connection to the `dyna-server`. The server uses this connection to push real-time updates to the client.
3.  **Live Updates**: When a resource is updated on the server (e.g., by another client), the `dyna-server` sends an `UpdateEvent` over the WebSocket to all connected clients. `lazy-py` receives this event and can notify the application, which can then update its state and UI accordingly.

## 5. Technical Design

`lazy-py` is built on top of `dyna-py` and `websockets`. It uses `asyncio` for its asynchronous operations, making it non-blocking and suitable for high-concurrency applications.

*   **Concurrency**: The `LazyClient` runs its own asyncio event loop in a separate thread to manage the WebSocket connection and handle incoming messages without blocking the main application thread.
*   **Data Structures**: Resources are stored in an in-memory dictionary, acting as a cache. This ensures that once a resource is fetched, subsequent `get()` calls are instantaneous.
*   **Error Handling**: The library includes robust error handling for network issues, connection failures, and server-side errors. The `on_update` callback receives an `UpdateEvent` object that includes an `error` field, allowing the application to handle issues gracefully.
*   **Compression**: `lazy-py` supports gzip compression for all communication with the `dyna-server`, reducing network bandwidth and improving performance.

## 6. Integration Examples

Here are some examples of how to use `lazy-py` in a Python application.

### Basic Usage

```python
import asyncio
from lazy_py import LazyClient

async def main():
    client = LazyClient()
    await client.connect("ws://localhost:8080/api/v1/ws")

    def on_update(event):
        print(f"Received update: {event}")

    client.on_update(on_update)

    # Fetch a single resource
    user = await client.get("acme.user.1")
    print(f"User: {user}")

    # Keep the script running to receive updates
    await asyncio.sleep(60)

if __name__ == "__main__":
    asyncio.run(main())
```

### Iterating Over All Resources

```python
import asyncio
from lazy_py import LazyClient

async def main():
    client = LazyClient()
    await client.connect("ws://localhost:8080/api/v1/ws")

    def process_resource(resource):
        print(f"Processing resource: {resource}")

    await client.for_each_all(process_resource)

if __name__ == "__main__":
    asyncio.run(main())
```

## 5. Technical Design

`lazy-py` is built on top of several popular and robust Python libraries:

*   **`asyncio`**: For managing asynchronous operations, enabling non-blocking network I/O.
*   **`websockets`**: For handling the WebSocket communication with the `dyna-server`.
*   **`aiohttp`**: For making asynchronous HTTP requests to fetch resources.

### Concurrency Model

The `LazyClient` uses an actor-like model for managing its state and network connections. A long-running `asyncio` task is spawned when `connect()` is called, which is responsible for maintaining the WebSocket connection, listening for incoming messages, and dispatching `UpdateEvent`s to the registered callback.

All public methods of the `LazyClient` are `async` and are safe to be called from multiple concurrent tasks.

### Error Handling

Network errors, such as connection failures or timeouts, are raised as exceptions. The application is responsible for catching these exceptions and implementing its own retry logic if desired.

## 6. Integration Examples

Here is a complete, runnable example of how to use `lazy-py` to connect to a Dyna server, fetch a resource, and listen for real-time updates.

```python
import asyncio
from lazy_py import LazyClient, UpdateEvent

async def main():
    client = LazyClient()
    await client.connect("ws://localhost:8080/api/v1/ws")

    def on_update(event: UpdateEvent):
        print(f"Received update for {event.resource_id}: {event.patch}")

    client.on_update(on_update)

    # Lazily fetch a resource
    user = await client.get("acme.user.123")
    print(f"Fetched user: {user}")

    # Keep the script running to listen for updates
    try:
        while True:
            await asyncio.sleep(1)
    except KeyboardInterrupt:
        print("Exiting...")

if __name__ == "__main__":
    asyncio.run(main())
```

### Dependency on dyna-py

`lazy-py` is built directly on top of the `dyna-py` library, which provides the core Python bindings to the underlying Rust implementation of the Dyna protocol. This layered approach allows `lazy-py` to focus exclusively on the lazy-loading and real-time update logic, while `dyna-py` handles the lower-level details of changeset creation, patch application, and communication with the `dyna-server`'s REST API.

This separation of concerns results in a cleaner and more maintainable codebase for both libraries. `dyna-py` provides the foundational building blocks, and `lazy-py` provides a higher-level, more specialized API for a specific use case.
